# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 2 replaces Phase 1's single hardcoded game screen with a real product shell: a
home menu (vertical list — Letters, Numbers, Alphabet, Statistics, Settings, Share,
Quit) over an animated parallax background, three fullscreen gameplay modes (Letters,
Numbers, Alphabet — visually identical to Phase 1's single-letter loop, just different
character pools), and two **windowed** (non-fullscreen) stub screens (Statistics,
Settings) whose real content arrives in Phases 3-4. Per `02-CONTEXT.md`, this is the
first phase where the app's secondary (`--color-surface`) and accent tokens get real
on-screen chrome usage — Phase 1's 60/30/10 palette was declared but only ~90%+
dominant in practice; this phase is where that ratio starts to actually apply.

## Assumptions (gaps CONTEXT.md left open)

`02-CONTEXT.md`'s 16 decisions are treated as authoritative. The items below fill gaps
it left open — flagging them here so planner/executor/checker can challenge any of them.

1. **shadcn/design-system tooling = none**, unchanged from Phase 1. This project is
   explicitly vanilla TypeScript with no framework (CLAUDE.md's "What NOT to Use"
   table); shadcn requires React. The shadcn gate resolves to "not applicable," not
   "declined" — re-asking this each phase would contradict CLAUDE.md's locked stack.
2. **Menu row order**: Letters, Numbers, Alphabet, Statistics, Settings, Share, Quit —
   gameplay modes first (primary group), utility rows second (Statistics/Settings/
   Share), Quit last with extra top margin to read as a distinct, deliberate exit
   action. CONTEXT.md fixes the *set* of rows (MENU-01) and Share's row-vs-icon
   treatment, not the exact order.
3. **First menu item ("Letters") is auto-focused on load** so Up/Down/Enter keyboard
   navigation works immediately with no initial Tab press required — matches
   CONTEXT.md's "supports both Up/Down arrow + Enter AND mouse/touch click" decision.
4. **Keyboard navigation wraps around** (Down from Quit → Letters; Up from Letters →
   Quit) — standard accessible menu pattern, no dead ends for a parent operating the
   menu.
5. **Windowed screens (Statistics, Settings) return to the home menu via Escape**
   (reusing the same key convention CONTEXT.md establishes for gameplay modes) **and**
   a visible "← Back" text row for mouse/touch parity, since CONTEXT.md specifies these
   screens are windowed but doesn't specify their exit affordance.
6. **Windowed screens render as a centered panel over the same animated menu
   background** (not a separate blank page) — keeps the "no full-page flash" visual
   continuity established in Phase 1 (CORE-05) and avoids a jarring context switch for
   a screen that's still one click from the menu.
7. **Numbers/Alphabet modes reuse Phase 1's Display typography, color tokens, and
   correct/incorrect motion contract unchanged** — only the character pool changes
   (digits 0-9 for Numbers; sequential A→Z for Alphabet vs. Letters' random A-Z). Not
   re-derived in full below; see Phase 1's `01-UI-SPEC.md` Motion & Celebration
   Contract for the base values this phase inherits verbatim.
8. **Icon library = none** (hand-authored inline SVG), consistent with Phase 1's
   zero-extra-dependency stance and CLAUDE.md naming canvas-confetti as "the only
   runtime dependency this project needs." Exactly one icon is needed this phase (the
   Share row's icon).

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1, now actually
exercised by menu/panel chrome:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Focus-underline offset (menu item) |
| sm | 8px | Share row icon-to-label gap |
| md | 16px | Root safe-area edge padding (unchanged from Phase 1); windowed-panel internal row gaps |
| lg | 24px | Vertical gap between menu rows within a group; windowed-panel body padding |
| xl | 32px | Menu-column top/bottom breathing room; extra top margin isolating the Quit row; windowed-panel outer padding |
| 2xl | 48px | Reserved (not exercised this phase) |
| 3xl | 64px | Reserved (not exercised this phase) |

Exceptions:
- **Menu item tap target**: `min-height: 56px` (8×7 — still an 8-point multiple, but
  outside the named token list) — ensures every row, including single-line text-only
  items, meets a comfortable click/tap target for the parent operating the menu, per
  CONTEXT.md's "large tap targets, no button chrome" decision.
- **Menu row font-size is responsive, not fixed**: `clamp(20px, 4vh, 28px)` (see
  Typography) so 7 rows + gaps never overflow a short landscape-phone viewport before
  falling back to scroll (see UI Considerations → overflow).
- **Windowed panel max-width**: 480px, centered — not a spacing-scale value (it's a
  layout constraint, not a spacing token), consistent with Phase 1's precedent of
  declaring non-token layout constraints (e.g. Phase 1's Display `clamp(...)`) where
  the 8-point scale doesn't apply.
- Menu column max-width: 400px, centered — same rationale.

## Typography

Unchanged roles/sizes from Phase 1 (still exactly 4 sizes, 2 weights) — this phase is
the first to actually render Label/Body/Heading on screen (Phase 1 only used Display):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 28px (responsive: `clamp(20px, 4vh, 28px)` for menu rows — see Spacing exceptions) | 700 (bold) | 1.2 |
| Display | `clamp(140px, min(45vh, 40vw), 560px)` | 700 (bold) | 1 |

**Role usage this phase:**
- **Label** — "← Back" row on windowed screens; "Copied!" share feedback text.
- **Body** — Statistics/Settings stub body copy (see Copywriting Contract).
- **Heading** — every menu row (Letters, Numbers, Alphabet, Statistics, Settings,
  Share, Quit); windowed-panel screen titles ("Statistics", "Settings").
- **Display** — unchanged from Phase 1: the single target letter/digit during gameplay
  (Letters, Numbers, Alphabet modes), uppercase always (letters), numerals as-is
  (digits have no case).

Two weights total, per contract: 400 and 700. No new sizes introduced.

## Color

Unchanged tokens from Phase 1 — this phase is where Secondary and Accent finally get
real on-screen surface area (Phase 1's palette was ~90%+ dominant background):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0E1B` (`--color-bg`) | Full-bleed background layer beneath the menu parallax; base layer of gameplay screens (unchanged) |
| Secondary (30%) | `#1E2340` (`--color-surface`) | Windowed panel background (Statistics/Settings); parallax background's mid-layer gradient blobs; unfocused menu-row text sits directly on Dominant, not Secondary |
| Accent (10%) | `#8B7FFF` (`--color-accent`) | Focused/selected menu-row glow + underline (CONTEXT.md decision); Share icon on focus/hover; gameplay celebration (unchanged from Phase 1) |
| Foreground (on-dark) | `#F3F1FA` (`--color-fg`) | Default (unfocused) menu-row text color; windowed-panel body/heading text; unchanged gameplay target color |
| Destructive | `#C4607A` (`--color-destructive`) | Still reserved/unused this phase — Quit has no confirmation (CONTEXT.md explicit) and causes no data loss; first real usage arrives with Reset Stats in Phase 4 |

**Accent reserved for:** the focused/selected menu row's glow + underline indicator
(reusing `--color-accent`, per CONTEXT.md); the Share row's icon color on focus/hover;
the correct-match celebration glow + confetti anchor hue (unchanged from Phase 1). Not
used for: resting/unfocused menu text, panel chrome, or any static "always-on" element —
this keeps the accent feeling reserved for "this is currently selected / this is
working" rather than diluted into everyday chrome.

**Menu background gradient layers** (see Home Menu & Background Contract below) use
`--color-bg` and `--color-surface` at low opacity — no new hex values introduced.

## Home Menu & Background Contract

*(Supplementary section — CONTEXT.md explicitly delegates the exact CSS/animation
implementation of the parallax background and focus indicator to "Claude's
Discretion." Concrete values specified here so the executor isn't guessing, following
Phase 1's precedent of specifying motion contracts outside the template's default rows.)*

### Layout

- Full-viewport flex column, menu content centered horizontally and vertically.
- Menu column: `max-width: 400px`, centered.
- Row order (top to bottom): `Letters`, `Numbers`, `Alphabet` (24px gaps) → 24px group
  gap → `Statistics`, `Settings`, `Share` (24px gaps) → 32px group gap → `Quit`.
- Each row: `min-height: 56px`, plain text (Heading role, 700 weight), no background,
  no border, no button chrome — flush-left aligned within the 400px column.
- Share row only: inline SVG icon (20×20, outlined "export" glyph — a box with an
  upward arrow, `stroke: currentColor`, `stroke-width: 2`, no fill, so it inherits
  `--color-fg` at rest and `--color-accent` when focused) + `sm` (8px) gap + "Share"
  text label, vertically centered.

### Focus/selection indicator

- Applies to whichever row is currently keyboard-focused or mouse-hovered.
- Text color shifts from `--color-fg` to `--color-accent`.
- A thin (2px) accent-color underline appears beneath the row's text width (not full
  row width), with a soft glow:
  ```css
  .menu-item.focused {
    color: var(--color-accent);
  }
  .menu-item.focused::after {
    content: '';
    display: block;
    height: 2px;
    margin-top: 4px;
    background: var(--color-accent);
    box-shadow: 0 0 8px var(--color-accent);
  }
  ```
- Transition: `color 100ms ease-out` on the text, no transition on the underline
  (appears/disappears instantly with focus change — avoids a laggy-feeling menu).

### Parallax background

- Three stacked full-viewport layers, `position: fixed`, behind all content
  (`z-index: -1`):
  1. **Base**: solid `--color-bg` — matches Phase 1's pre-hydration paint color, no
     flash on load.
  2. **Blob layer A**: 2-3 large soft `radial-gradient` blobs using `--color-surface`
     at ~10% opacity, `background-size: 150% 150%`, animated via `transform:
     translate(...)` drifting slowly (`40s ease-in-out infinite alternate`).
  3. **Blob layer B**: 1-2 blobs using `--color-accent` at ~6% opacity (kept low —
     accent must still read as "reserved," not ambient), drifting at a different
     duration (`65s ease-in-out infinite alternate`) so the differing speeds create
     the parallax read.
- `prefers-reduced-motion: reduce`: both blob layers freeze to their static starting
  position (no `animation`), matching Phase 1's existing reduced-motion pattern for
  the confetti burst.
- No image assets (CONTEXT.md explicit) — pure CSS gradients + `transform` only.

### Windowed panels (Statistics, Settings)

- Rendered as a centered panel (`max-width: 480px`) over the same three-layer
  background described above (assumption 6) — never a separate blank page.
- Panel background: `--color-surface`, `border-radius: 12px`, padding `xl` (32px).
- Panel contents, top to bottom: `← Back` row (Label, 14px, `--color-fg`, focus/hover
  shifts to `--color-accent` — same interaction pattern as menu rows) → 16px gap →
  screen title (Heading, "Statistics" or "Settings") → 16px gap → stub body copy
  (Body, 16px — see Copywriting Contract).
- Exit: `← Back` row (click/Enter) or `Escape` key — both return to the home menu via
  the same 100ms opacity crossfade used elsewhere (assumption 5).

## Fullscreen & Navigation Contract

*(Supplementary section — CONTEXT.md locks the behavioral rules; concrete
sequencing/timing specified here so FULL-01/02/03 aren't left ambiguous for the
executor.)*

### Entering a mode (Letters / Numbers / Alphabet)

1. On row activation (click/Enter), the game screen crossfades in immediately (100ms
   opacity, reusing Phase 1's established transition) — **not gated** on the
   `requestFullscreen()` promise resolving.
2. `requestFullscreen()` is called in parallel. If it resolves, the browser's native
   fullscreen chrome takes over. If it rejects or is unavailable (iOS Safari
   variance — flagged in Phase 1 research), gameplay continues windowed with **no
   error UI, no retry prompt** — CONTEXT.md explicit: "fullscreen success is never a
   gate on starting a mode."
3. Gameplay screen itself (Display letter, correct/incorrect motion contract) is
   pixel-identical to Phase 1's `01-UI-SPEC.md`, just with the mode's character pool
   swapped in (assumption 7).

### Exiting (Quit / Escape / OS gesture / unexpected exit)

1. The native `fullscreenchange` event is the single source of truth (CONTEXT.md
   explicit) — every path (explicit Quit-equivalent action, Escape while in a mode, OS
   swipe-to-exit) fires this event identically; there is no separate manual-exit vs.
   auto-exit code path.
2. On `fullscreenchange` reporting `document.fullscreenElement === null`: the app
   transitions back to the home menu via the same 100ms opacity crossfade, with the
   first menu row (`Letters`) re-focused (assumption 3, reapplied — not "last used
   mode," to keep behavior predictable for a parent).
3. `exitFullscreen()` itself (when called programmatically, e.g. from an in-mode
   Escape handler) is synchronous and immediate — "no fade, no confirmation dialog"
   (CONTEXT.md explicit). The *visual* crossfade in step 2 is the resync reaction to
   the fullscreenchange event, not a delay gating the exit itself.

### Alphabet mode Z-completion celebration

- Reuses Phase 1's `celebrate()` function (per CLAUDE.md: "reuse the same
  canvas-confetti call with a higher particleCount/wider spread... rather than
  introducing a second animation system") — not a new animation system.
- On reaching Z and looping back to A: the target swaps instantly to `A` (same
  instant-swap sequencing as every other correct match, Phase 1 assumption 7 —
  unchanged), and **three** sequential `celebrate()`-style bursts fire at 0ms/120ms/
  240ms from left/center/right screen positions (rather than one burst anchored to the
  glyph), each with:
  ```
  particleCount: 120   (vs 40 normal — ~3x)
  spread: 100           (vs 60 normal)
  startVelocity: 35      (vs 25 normal)
  ticks: 200             (vs 150 normal)
  gravity: 1
  scalar: 1.1            (vs 0.8 normal — slightly larger particles)
  colors: CONFETTI_COLORS  (unchanged palette, no new hex values)
  ```
- Plays fullscreen as normal gameplay, no special fullscreen handling (CONTEXT.md
  explicit) — this is purely a bigger version of the existing celebration vocabulary.

### Share affordance

1. On activation, attempt `navigator.clipboard.writeText(window.location.href)`.
2. On success: the "Share" label text is replaced in place with "Copied!" for ~1.5s,
   then reverts — no toast, no confetti (CONTEXT.md explicit).
3. On `navigator.clipboard` unavailable/denied: fall back to a temporary hidden
   `<input>` + `document.execCommand('copy')`.
4. If that also fails: render the Error state from the Copywriting Contract — copy
   text + a selectable `<input readonly value={window.location.href}>` inline below
   the Share row.
5. URL copied is `window.location.href` as-is, including any `URLSearchParams` state
   (CONTEXT.md explicit) — never a hardcoded canonical root.

| Category | Element(s) | Status | Resolution / Reason |
