## Decisions implemented by this plan

The full Phase 2 decision index (D-01 … D-19) lives in `02-01-PLAN.md`. The four this plan owns:

| ID | Decision |
|----|----------|
| D-13 | The share control is its own menu row (icon + "Share" text label), not a corner icon |
| D-14 | On successful copy, feedback is a brief inline text change ("Copied!" for ~1.5s) — no toast, no confetti |
| D-15 | Clipboard fallback chain: the async clipboard write, then the legacy copy command via a temporary hidden input, then a selectable text box |
| D-16 | The URL copied is `window.location.href` as-is, including any query state |

No other decision is touched. In particular, `stats` and `settings` row activation stays undispatched:
`02-CONTEXT.md`'s phase boundary and `REQUIREMENTS.md`'s phase map put those screens' real content in
Phase 3 (SET-01/02) and Phase 4 (STAT-01/02); MENU-01 only requires the rows to be *displayed*, which
plan 02-01 already satisfies.

<assumption_delta_decision>
**Noun:** "copy mechanism" — singular→plural transition (a single `navigator.clipboard` write becomes
three mechanisms: the async clipboard write, the legacy copy command, and a human copying by hand).
**Decision:** DEMOTE to an ordered degradation chain, not a strategy set. There is exactly one exported
entry point, `shareCurrentUrl()`, which tries the tiers in a fixed order and returns a discriminated
`ShareResult`. Do **not** introduce a strategy interface, a registry of copy providers, a
`preferredMechanism` option, or any way for a caller to select a tier.
**Rationale:** the three tiers are not interchangeable — they are strictly worse in order, and the
ordering *is* the design (D-15 locks it). A pluggable abstraction would invite a future caller to pick
the legacy tier first, silently reintroducing the deprecated API on browsers that support the modern one,
and would add a seam with no second consumer. One entry point, one order, one result union.
</assumption_delta_decision>

export type ShareResult = 'copied' | 'fallback-executed' | 'manual-required'

`src/menu.ts`'s exported surface is unchanged — `MenuRow`, `MENU_ROWS`, `MENU_LABELS`, `MenuHandlers`,

`onShare` member to `MenuHandlers`**: `02-PATTERNS.md`'s `src/menu.ts` section maps the share dispatch
inside the menu module itself (`import { shareCurrentUrl } from './clipboard'`), because the Copied! swap
and the fallback panel are menu presentation, not app orchestration. Keeping the handler interface fixed
is also what keeps `src/main.ts` out of this plan's `files_modified` entirely.

| Boundary | Description |
|----------|-------------|
| App → system clipboard | The app hands a string to an OS-level buffer that every other application on the machine can read |
