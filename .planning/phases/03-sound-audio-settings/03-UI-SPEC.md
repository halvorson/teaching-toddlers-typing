# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 3 (AUDIO-01, AUDIO-02, SET-01) adds **exactly one new visual element**: a second
`.toggle-row` in the existing Settings panel, labeled `Sound`, reusing the toggle-switch
visual/markup pattern `02.1-UI-SPEC.md` already built and shipped in full (`src/settings.ts`,
`.toggle-row`/`.toggle-switch`/`.toggle-switch__thumb` in `src/style.css`). The chime
(synthesized `OscillatorNode`/`GainNode`) and the spoken letter/number (`SpeechSynthesis`) are
both **non-visual** — they have no on-screen representation, no loading/error UI, and no state
to render (per `03-CONTEXT.md`: all audio failures degrade silently, matching the
already-established `celebrate.ts`/`clipboard.ts` precedent). Accordingly, this UI-SPEC does
**not** invent new design tokens, typography, or color usage — every section below either says
"unchanged from Phase 2.1" or specifies only the one new toggle row's copy/ordering/default
state that Phase 2.1 didn't already cover.

No new screens, no new panel, no new icon, no new copy beyond one label string.

## Assumptions (gaps CONTEXT.md left open)

1. **Toggle label text = `Sound`** (exact, case-sensitive). `03-CONTEXT.md` scopes the toggle to
   "enable/disable sound (chime + spoken letter)" per SET-01's literal wording but leaves the
   exact button label to discretion. `Sound` is chosen over a longer label (e.g. "Sound effects
   & voice") to match the existing row's terse, single-word-concept style (`Reset trail on
   mistake` is a full sentence but names one concrete behavior; `Sound` names one concrete
   on/off concept, appropriately shorter since it isn't describing a conditional behavior).
   `aria-label` mirrors the visible label exactly, matching the existing row's pattern.
2. **Row order: existing "Reset trail on mistake" row stays first, "Sound" row is appended
   second**, directly beneath it. `03-CONTEXT.md`'s own code_context says "a second `.toggle-row`
   beneath the existing one," and this preserves the existing row's established position rather
   than reordering shipped UI.
3. **Default `aria-checked` state = `"true"`** (sound ON by default), the opposite default from
   the trail-reset toggle's `"false"`. This directly reflects `03-CONTEXT.md`'s explicit decision
   (`soundEnabled: true` default) — flagged here because it means the two toggle rows will render
   with visibly different initial ON/OFF states, which is intentional, not an inconsistency.
4. **No new focus-order requirement beyond DOM order.** Tab/click order becomes: `← Back` →
   "Reset trail on mistake" switch → "Sound" switch, matching visual top-to-bottom order with no
   custom `tabindex`.
5. **Chime and speech are out of this UI-SPEC's state-coverage scope.** They have no visual
   representation to audit against the 6 design-quality dimensions (Copywriting, Visuals, Color,
   Typography, Spacing, Registry Safety) — their failure/success behavior is fully governed by
   `03-CONTEXT.md`'s "Audio Failure Handling & Edge Cases" section (silent degrade, independent
   chime/speech, no `prefers-reduced-motion` interaction) and is not restated here to avoid
   drift between two documents describing the same non-visual contract.

## Settings Screen & Toggle Contract (delta from Phase 2.1)

*(Supplementary section — specifies only what's new. The panel shell, focus/hover treatment of
`← Back`, Escape-to-exit, and the trail toggle's own row are all unchanged from Phase 2.1's full
specification and are not restated here.)*

### Panel contents, top to bottom (updated)

`← Back` row → 16px gap → panel title (`Settings`) → 16px gap → "Reset trail on mistake" toggle
row (unchanged, existing) → 16px gap → **"Sound" toggle row (new this phase)**.

### New toggle row markup

Identical structure to the existing row, only the label/aria-label/default state differ:

```html
<div class="toggle-row">
  <span class="toggle-row__label">Sound</span>
  <button type="button" role="switch" class="toggle-switch"
          aria-checked="true" aria-label="Sound">
    <span class="toggle-switch__thumb"></span>
  </button>
</div>
```

- Uses the exact same `.toggle-row`, `.toggle-switch`, `.toggle-switch__thumb` CSS classes
  already defined in `src/style.css` — **zero new CSS rules required** for this row's visual
  appearance.
- `aria-checked` initializes from `readSettings().soundEnabled` (default `true`), the mirror of
  how the existing row initializes from `readSettings().resetTrailOnMistake` (default `false`).
- Click/Enter/Space toggles `aria-checked` and persists via a **merged** write —
  `writeSettings({ ...readSettings(), soundEnabled: next })` — never a full-replace write, so
  toggling Sound never resets the trail-reset preference (and vice versa). This merge-write
  correction applies to both toggle rows' click handlers, per `03-CONTEXT.md`'s explicit
  instruction to fix the existing full-replace pattern.
- Focus-visible outline: unchanged `2px solid var(--color-accent)`, `outline-offset: 2px`.

### Persistence (delta)

- `AppSettings` interface extends to `{ version: 1, resetTrailOnMistake: boolean, soundEnabled:
  boolean }`, still `version: 1` (no schema-version bump — per-field default resolution instead,
  per `03-CONTEXT.md`).
- Default `soundEnabled: true` (contrast with `resetTrailOnMistake: false`) — see Assumption 3.
- Same try/catch silent-degrade-to-in-memory read/write contract as the existing field, unchanged.
