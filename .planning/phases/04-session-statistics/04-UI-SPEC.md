# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 4 (STAT-01..05, SET-02) gives the Statistics menu row its first real content — a windowed
panel, reusing the exact `.settings-panel` container Phase 2.1 built, showing two scalar stat
rows (Accuracy, Letters per minute) plus a five-bucket reaction-time histogram rendered as plain
CSS bars, and a one-click "Reset Stats" button. Settings gains exactly one new row: a
"View Statistics" link appended beneath the two existing toggles, satisfying SET-02 by routing
to the same Reset control rather than duplicating it.

Two new elements have **no prior visual precedent** in this codebase and are specified in full
below, following Phase 1/2.1's precedent of giving the executor exact numbers rather than
leaving them to invent: the **reaction-time histogram** (first data-visualization element in the
app) and the **destructive Reset button** (first genuine use of `--color-destructive`, which has
sat reserved-and-unused since Phase 1). Everything else — panel shell, typography, back/escape
exit — is unchanged from Phase 2.1/3 and is only referenced, not restated.

## Assumptions (gaps CONTEXT.md left open)

`04-CONTEXT.md`'s decisions are treated as authoritative. The items below fill gaps it
explicitly delegated to "Claude's Discretion" or left unstated.

1. **Statistics panel reuses the `.settings-panel` CSS class verbatim** as its root element's
   class (same 480px max-width, `--color-surface` background, 12px radius, 32px padding, 16px
   `row-gap` flex-column layout auto-spacing every top-level child) — this class was already
   generic panel chrome, not Settings-specific, matching CONTEXT.md's "reuses the existing
   windowed panel pattern" instruction literally.
2. **Empty-state copy = a single em dash "—"** for Accuracy, Letters-per-minute, AND the
   histogram (as a small caption beneath the bar row) — CONTEXT.md's Claude's-Discretion note
   explicitly asks for one consistent choice across all three; "—" is chosen over a sentence
   because it reads instantly to a parent glancing at a screen with no data yet, and because two
   of the three values (Accuracy, LPM) are inherently scalar and a dash is the natural "no value"
   glyph for a number; applying the identical glyph to the histogram keeps the "no data" signal
   visually and semantically identical across all three, rather than mixing a dash with a
   sentence.
3. **Numeric formats**: Accuracy = `Math.round(correctCount / (correctCount + incorrectCount) * 100)` + `%`
   (e.g. `92%`, no decimal). LPM = the CONTEXT.md formula, `.toFixed(1)` + `/min` (e.g. `8.3/min`).
   Not specified in CONTEXT.md; locked here so the executor isn't guessing at rounding/suffix.
4. **Histogram has no per-bucket numeric labels**, only the five fixed bucket-range labels
   (`<1s`, `1-2s`, `2-4s`, `4-8s`, `8s+`) beneath the bars. STAT-03 requires a histogram, not
   numeric annotations — keeping it purely visual matches "no charting library" simplicity and
   avoids a sixth typography instance.
5. **Reset button gets the app's first real `--color-destructive` usage** (border + text color,
   not a filled background) rather than staying neutral. Since STAT-04/CONTEXT.md explicitly rule
   out a confirmation dialog, the button's own color is the sole signal that this action is
   destructive — an unstyled neutral button next to the data it clears would under-communicate
   irreversibility.
6. **"View Statistics" link on Settings reuses `.panel-back`'s exact visual treatment** (14px/400
   Label role, `--color-fg` → `--color-accent` on hover/focus) under a new class name
   `.panel-link`, appended as the third row after the two toggles. Zero new visual language;
   only a new class name to keep its semantic role (content navigation, not back-navigation)
   distinct from `.panel-back`.
7. **Module names**: `stats-store.ts` (mirrors `settings-store.ts`) and `stats.ts` (mirrors
   `settings.ts`) — CONTEXT.md names these as its own suggested discretion call; recorded here for
   downstream consistency, not a UI-SPEC-owned decision.

Unchanged from Phases 1–3 — still exactly 4 sizes, 2 weights. No new sizes/weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|

**Role usage this phase:**
- **Label** — histogram section heading ("Reaction Time"), the five bucket-range labels beneath
  the bars, and the "View Statistics" link on Settings (all reuse `.panel-back`'s existing 14px

- **Body** — `.stat-row__label` text ("Accuracy", "Letters per minute"), the histogram empty-state

  Statistics panel title ("Statistics") also uses this role, unchanged pattern from Settings.
- **Display** — gameplay target letter/digit, unaffected by this phase.

Two weights total, per contract: 400 and 700. No new sizes or weights introduced.

fill, muted) and gives `--color-destructive` its **first real usage** since being reserved in
Phase 1:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0E1B` (`--color-bg`) | Unchanged |
| Secondary (30%) | `#1E2340` (`--color-surface`) | Unchanged — Statistics panel background (reuses `.settings-panel`) |
| Accent (10%) | `#8B7FFF` (`--color-accent`) | Unchanged base token; **NEW** muted derivation for histogram bars — see below |
| Foreground (on-dark) | `#F3F1FA` (`--color-fg`) | Unchanged — stat-row labels/values, panel title, bucket labels (at reduced opacity), Reset button thumb-equivalent N/A |
| Destructive | `#C4607A` (`--color-destructive`) | **NEW — first real usage.** Reset button border + text color (not a filled background), see Statistics Screen Contract below |

**Accent reserved for (extends Phase 3's list):**
- Focused/selected menu row glow + underline (unchanged).
- Share icon on focus/hover (unchanged).
- Correct-match celebration glow + confetti anchor hue (unchanged).
- Star-trail dot glow, muted `color-mix` (unchanged).
- Toggle-switch ON-state track fill, full strength (unchanged, both toggles).
- **NEW — reaction-histogram bar fill**, at `color-mix(in srgb, var(--color-accent) 55%, transparent)`
  — muted, not full-strength, because a static data bar is passive display, not an active
  control; keeping it below the toggle's full-strength treatment preserves the accent's "reserved

**Destructive reserved for:** the Reset Stats button only — border + text color at full

Not used for: resting/unfocused text, panel chrome background, bucket-range labels (dimmed
`--color-fg`, not accent or destructive), or either toggle's OFF-state track (unchanged).

### Bar-height calculation (behavior contract, for the executor)

- `maxCount = Math.max(...bucketCounts)`. If `maxCount === 0` (no correct matches recorded yet),
  every bar renders at the fixed `min-height: 4px` baseline (via the CSS default — no inline
  `height` needed) and `.reaction-histogram__empty` (`—`) is appended as the sixth child of
  `.reaction-histogram`.
- Otherwise, each bar's inline `height` = `Math.max(4, Math.round((count / maxCount) * 96))`px —
  the tallest bucket always renders at exactly 96px (the container height), every other bucket
  scales proportionally, and a zero-count bucket among non-zero others still renders its 4px
  floor rather than disappearing entirely (so all five bars remain visible and countable at a
  glance).
- Recomputed and re-rendered on every mount and immediately after Reset — no resize listener
  needed (values only change on new matches or reset, not on viewport changes).

### Reset behavior

- Clicking `.stats-reset` calls the stats-store's reset function (zeroes `correctCount`,
  `incorrectCount`, all five histogram buckets, and both timestamps), persists the zeroed record,
  then re-renders the panel in place using the same render path as initial mount — Accuracy and
  LPM both show `—`, all five bars drop to the 4px baseline, and the `—` empty caption reappears.
  No toast, no dialog, no page navigation.
