## 3-state sound control

### What each state controls

| Option | Description | Selected |
|--------|-------------|----------|
| Mutually exclusive (recommended) | Off = silent. Chime = chime only, no speech. Spoken letter = speech only, no chime. | ✓ |
| Escalating (chime always-on once enabled) | Off = silent. Chime = chime only. Spoken letter = chime + speech together. | |

**User's choice:** Mutually exclusive (recommended)

### Default state

| Option | Description | Selected |
|--------|-------------|----------|
| Chime (recommended) | Chime is the celebratory sound tied to Core Value; speech is more of a bonus/teaching layer. | ✓ |
| Spoken letter | Speech reinforces the letter/number name association. | |

**User's choice:** Chime (recommended)

### UI shape

| Option | Description | Selected |
|--------|-------------|----------|
| 3-segment control (recommended) | A single row with 3 side-by-side buttons/segments, one visibly active. | ✓ |
| Cycling button | Reuses the existing toggle-switch shape; each tap cycles through the 3 states. | |
| 3 radio-style rows | Three separate stacked rows, selecting one deselects the others. | |

**User's choice:** 3-segment control (recommended)
**Notes:** User asked that this component be built reusable (variable option count), since the session-cap control reuses the same shape with 4 options instead of 3.

## Session cap control & value

### Input shape

| Option | Description | Selected |
|--------|-------------|----------|
| Preset buttons (recommended) | A row of fixed choices as tappable buttons — zero typing. | ✓ (as the reusable segmented control) |
| Stepper (+ / − buttons) | A number readout with +/− buttons to adjust by 1 (or 5). | |
| Slider | A drag slider across a min–max range. | |

**User's choice:** Reuse the 3-segment control pattern from sound, generalized into a reusable N-segment component.

### Option values and default

**User's choice (after two rounds of clarification):** 4 options — 10 / 26 / 50 / No Cap. Default 50.
**Notes:** User's first pass suggested 10/25/50/No Cap; then corrected to swap 25→26 ("26 gets us through one lap of the alphabet, so could simplify things"), which read ambiguously as possibly also dropping "No Cap." A follow-up clarifying question confirmed "No Cap" stays as the 4th option — final answer is 10/26/50/No Cap, default 50.

## Game Over screen & one-more-letter

### Screen style

| Option | Description | Selected |
|--------|-------------|----------|
| Full-immersive (recommended) | Big centered congratulatory message filling the screen, matching the celebration's scale. | ✓ |
| Windowed panel | Reuses the centered-card pattern from Settings/Stats. | |

**User's choice:** Full-immersive (recommended)

### Actions on screen

| Option | Description | Selected |
|--------|-------------|----------|
| One more letter + Back to menu (recommended) | Two actions only. | ✓ |
| One more letter + Play again (same mode) + Back to menu | Three actions, including a direct same-mode restart. | |

**User's choice:** One more letter + Back to menu (recommended)

### "One more letter" repeatability

| Option | Description | Selected |
|--------|-------------|----------|
| Repeatable every time (recommended) | Each time the extended cap is reached, Game Over reappears with the option to extend again. | (superseded — see notes) |
| One-time only per session | The override can be used once; no further extension after that. | |

**User's choice:** Neither literal option — user redirected to a third mechanic during the answer.
**Notes:** User's actual intent: using "One more letter" removes the cap entirely for the rest of that session (e.g. cap 26 → hit it → uncapped up to 200+ without the Game Over screen reappearing). The configured cap is restored only when a new session begins (return to menu, re-enter a mode). This is captured as D-14 in CONTEXT.md and flagged there as the single most load-bearing, non-obvious decision in this phase — it explicitly overrides a more literal "+1 per use" reading of SESSION-04's wording.
