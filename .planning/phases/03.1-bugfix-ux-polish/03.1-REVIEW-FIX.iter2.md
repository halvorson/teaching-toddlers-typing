## Fixed Issues

### CR-01: Menu's roving-focus keydown handler is not scoped to menu buttons, hijacking keyboard input inside the Share manual-copy fallback box

**Files modified:** `src/menu.ts`
**Commit:** `effc33e`
**Applied fix:** Added the same `target.closest<HTMLButtonElement>('button[data-row]')` guard used by `handleClick`, `handleHover`, and `handleFocusIn` to the top of `handleKeydown`, so Arrow/Home/End keydowns bubbling up from the Share row's manual-copy fallback `<input>` (a descendant of `nav`) are no longer intercepted and no longer yank focus away from that box.

### WR-01: `unmountMenu()` doesn't remove the menu's outer wrapper — leaves an orphaned empty `<div class="home-menu">` behind

**Files modified:** `src/menu.ts`
**Commit:** `eed195c`
**Applied fix:** Added a new module-level `mountedWrapper` variable, set it to the outer `wrapper` div in `mountMenu()` (the element actually appended to `container`), and changed `unmountMenu()`'s cleanup to operate on `mountedWrapper.parentElement.replaceChildren()` instead of `mountedNav.parentElement.replaceChildren()`, so the real container (not just the wrapper's children) is emptied. `mountedWrapper` is reset to `null` alongside `mountedNav` at the end of `unmountMenu()`.

### WR-02: Concurrent `runShare()` invocations aren't guarded within a single mount, allowing duplicate fallback panels / stale timers

**Files modified:** `src/menu.ts`
**Commit:** `64f7a81`
**Applied fix:** Added a module-level `sharePending` boolean re-entrancy guard. `runShare()` now early-returns if a previous invocation is still in flight, sets `sharePending = true` before awaiting `shareCurrentUrl()`, and clears it in a `finally` block so a double-click/tap on the Share row before the first call resolves can no longer produce a second orphaned fallback panel or an uncancelled "Copied!" revert timer.

### WR-03: `voiceschanged` listener is registered `{ once: true }`, but some browsers populate voices progressively

**Files modified:** `src/audio.ts`
**Commit:** `a668842`
**Applied fix:** Removed the `{ once: true }` option from the `voiceschanged` listener in `primeVoices()` so `cachedVoices` resyncs from `getVoices()` on every firing, not just the first — reconciling Chromium browsers that populate the voice list incrementally across multiple events.
