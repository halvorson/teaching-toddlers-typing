## Tests

### 1. MENU-04 — drifting parallax background visibly rendering
expected: The two drifting layers are visibly animating on the home menu and disappear during gameplay.
result: **ISSUE (initial check) → FIXED (follow-up)**. User first-hand report on the live deployed
  site (before the follow-up fix): background not visible. Live diagnosis via claude-in-chrome found
  the real root cause was NOT the color-mix() hypothesis this phase's plan targeted — it was
  `index.html`'s inline `html, body { background: #0A0E1B; }` rule causing canvas-background
  propagation to mask `position: fixed` + negative-`z-index` layers. Fixed in commit `dfbe03d`
  (scoped the background to `body` only). Verified visually via local `npm run preview` — drift
  layers now clearly visible. **Awaiting user re-confirmation on the redeployed live site.**

### 2. TRAIL-03 — star trail visibly rendering during gameplay
expected: |
  Play any mode and get 2-3 correct matches. Glowing accent-tinted stars visibly
  accumulate on screen. Return to the menu and confirm the trail is hidden. If stars
  are still invisible, run `document.querySelectorAll('.star-trail__star').length` in
  DevTools to disambiguate a CSS-only visibility cause from a DOM-append bug.
result: **ISSUE (initial check) → FIXED (follow-up)**. Same root cause and same fix as MENU-04
  (both are `position: fixed` + negative-`z-index` layers masked by the same canvas-background
  bug). `document.querySelectorAll('.star-trail__star').length` confirmed stars WERE being
  correctly appended to the DOM even while invisible (ruling out a DOM-append bug, confirming
  CSS-only visibility cause). Verified visually via local `npm run preview` — stars now visible
  during gameplay. **Awaiting user re-confirmation on the redeployed live site.**
