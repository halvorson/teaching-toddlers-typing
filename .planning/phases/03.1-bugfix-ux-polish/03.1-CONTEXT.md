**Gathered:** 2026-08-14

<domain>
## Phase Boundary

The live app matches what was actually designed and reviewed. Four of five requirements
are regression fixes / a doc correction against behavior already fully specified in

<decisions>
## Implementation Decisions

### Menu Title & Left-Alignment Layout
- The home menu column sits with a fixed left margin/padding (not pinned to the literal
  edge), staying vertically centered — Phase 2's vertical centering is preserved, only
  the horizontal centering is removed, matching Slay the Spire's left-docked column.
- The on-screen title ("Teaching Toddlers Typing") sits directly above the menu list,
  sharing the same left margin as the list — title and list read as one coherent
  left-docked block, per Slay the Spire's title-over-list composition.
- Title visual treatment: a large heading using the existing `--color-fg`/
  `--color-accent` palette tokens — no new font or image assets, pure CSS, consistent
  with the established pearlescent theme.
- This left-alignment change applies to the home menu only. Settings and Stats remain
  separate windowed (centered) panels per Phase 2's existing decision — MENU-05's
  wording ("the menu list") scopes this to the home menu specifically.

### Claude's Discretion (bugfix items — behavior already fully specified, root-cause work only)
- **AUDIO-03** (TTS says "Capital E" instead of "E"): root cause identified in
  `src/audio.ts` — `speakTarget()` assumes "English voices read a bare capital letter as
  its letter name" (see comment above `DIGIT_WORDS`), which is false on at least one
  real voice/OS combination in live use. Fix by explicitly mapping A-Z to their
  letter-name pronunciation, following the same lookup-table pattern already used for
  `DIGIT_WORDS`, removing the false assumption rather than relying on default voice
  behavior.
- **MENU-04** (drifting parallax background not rendering live): the `body::before`/
  `body::after` CSS and `data-chrome` gating already exist and are structurally correct
  per Phase 2's CONTEXT.md. Root-cause why it doesn't render in the deployed build
  (candidates: `#app` stacking/opacity/z-index, production CSS bundling/ordering,
  `prefers-reduced-motion` media query firing unexpectedly on the target device) and
  restore visibility. No new visual design — the already-agreed background must simply
  become visible.
- **TRAIL-03** (star trail not rendering live): same investigative pattern — `#star-trail`
  and its `data-chrome`-driven opacity gating already exist per Phase 2.1's CONTEXT.md.
  Root-cause why it's invisible live (candidates: z-index/stacking relative to `#app`,
  stars never actually being appended to the DOM, an opacity/transition timing issue)
  and fix. No new visual decisions — restore the already-built, already-verified trail.
- **DOCS-01** (branding correction): mechanical find/replace of "Keyboard Quest" with
  "Teaching Toddlers Typing" in `.claude/CLAUDE.md` and `.planning/PROJECT.md` (which
  still has the stale name as of this phase — confirmed via direct read). No ambiguity;
  every other tracked doc (ROADMAP.md, REQUIREMENTS.md) was already corrected earlier
  this session per STATE.md's decision log.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `src/audio.ts` — `DIGIT_WORDS` lookup table pattern (digit glyph → English word)
  should be mirrored for A-Z → letter-name pronunciation in `speakTarget()`, replacing
  the current fallback-to-bare-character assumption.
- `src/style.css` — `body::before`/`body::after` (drifting parallax, lines ~13-56) and
  `#star-trail` (lines ~65-90+) already implement the full visual spec from Phase 2 and
  Phase 2.1 — both gated by `body[data-chrome="game"]` in opposite directions (background
  hidden during gameplay, trail hidden on menu). Root cause of both being invisible live
  is almost certainly a stacking/z-index or build-output issue, not a missing feature.
- `src/menu.ts` — `mountMenu()` builds a `<nav>` element into `#app`; `#app` currently has
  `display: flex; align-items: center; justify-content: center` (style.css ~line 108),
  which horizontally centers the whole nav block — this is the rule to change for
  left-alignment. Row-level `text-align: left` already exists within each button.
- `index.html` — confirms `<title>Teaching Toddlers Typing</title>` is already correct;
  the stale "Keyboard Quest" name only lives in planning docs (`.claude/CLAUDE.md`,
  `.planning/PROJECT.md`), not in shipped app code.

### Established Patterns
- No image assets — all visual treatment (background, trail, title) is pure CSS using
  the `--color-bg`/`--color-surface`/`--color-accent`/`--color-fg` custom properties.
- `data-chrome` attribute on `<body>` (`main.ts`) is the single source of truth for
  menu-vs-game visual state; any fix to background/trail visibility should stay within
  this existing mechanism, not introduce a second one.
- `prefers-reduced-motion` guards already exist per-animation-site (celebrate.ts,
  background CSS) — any background/trail fix must preserve this, not bypass it.

### Integration Points
- `main.ts`'s `mountScreen()` sets `document.body.dataset.chrome` — no changes needed
  here for the bugfixes; the fixes are CSS/JS root-cause corrections within existing
  files.
- `src/menu.ts`'s `mountMenu()` is where the new title element gets inserted, immediately
  before/above the existing `<nav>` row list.
