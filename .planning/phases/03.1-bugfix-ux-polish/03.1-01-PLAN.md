## Phase Goal (MVP framing note)

ROADMAP.md's Phase 3.1 `**Goal:**` line is not in "As a / I want to / so that" format — it is
a bugfix/regression-restoration goal, not a new-capability user story. Per the user-story
template's "do not invent a story" rule, no story is fabricated here. Goal, verbatim from
ROADMAP.md:

> The live app matches what was actually designed and reviewed — visible menu background
> motion, a visible star trail, correct TTS pronunciation, a left-aligned Slay-the-Spire-style
> menu with an on-screen title, and consistent "Teaching Toddlers Typing" branding everywhere
> (never "Keyboard Quest")

This plan covers the visual-layer half of that goal: MENU-04, TRAIL-03, MENU-05.

## Flagged Assumptions (specless-probe edge items left unresolved by design)

Per the phase's edge-coverage probe, MENU-04 and TRAIL-03 both classified as `unclassified`
(no deterministic shape category applied) and — per protocol — MUST stay `unresolved`, never
silently auto-resolved. RESEARCH.md's own root-cause analysis found **no structural CSS bug**
in `body::before`/`body::after`/`#star-trail` (byte-identical live-vs-local build diff, correct
z-index/stacking math, correct `data-chrome` gating) — the live-invisibility root cause is
genuinely unconfirmed because no browser-automation tool was available during research. Task 2
and Task 3 below apply the defensive `color-mix()` cascade-fallback fix RESEARCH.md recommends
as cheap, non-breaking insurance regardless of root cause, but **do not silently treat that fix
as proof the bug is fixed** — each task's `human-check` step requires an actual live-browser
confirmation, and explicitly instructs capturing a follow-up gap (not a silent pass) if the
defensive fix does not resolve visibility.

## Artifacts This Phase Produces (this plan's share)

- `src/menu.ts`: new `.home-menu` wrapper `<div>`, new `.home-menu__title` `<h1>` element
  (both created inside `mountMenu()`)

  `--color-surface`/`--color-accent`)

<objective>
Restore the two previously-built-but-invisible-live visual layers (drifting parallax
background, star trail) via a defensive CSS cascade-fallback fix, and add the one net-new
visual element this phase introduces: a left-aligned home menu with an on-screen
"Teaching Toddlers Typing" title, implemented as a single wrapper so title and list always
share one left-margin source.

Purpose: the live deployed app currently diverges from what was designed/reviewed in Phase 2
and Phase 2.1 (MENU-04, TRAIL-03) and needs the Slay-the-Spire-style left-docked menu layout
CONTEXT.md locked in for this phase (MENU-05).
Output: `src/menu.ts` renders a `.home-menu` wrapper (title + nav) instead of a bare nav;
`src/style.css` gains cascade-fallback declarations and the new `.home-menu`/`.home-menu__title`
layout rules.
</objective>
