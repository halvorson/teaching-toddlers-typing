# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 1 ships exactly one screen: a full-viewport, single-letter target display with a
physical-keyboard input loop. Per `01-CONTEXT.md`: no menu, no fullscreen, no audio, no
stats — those arrive in Phases 2-4. The page loads directly into gameplay (no splash/
"get ready" gate). This contract is deliberately narrow — most template rows that assume
menus, forms, or lists are marked "not applicable" with a stated reason rather than
padded out with speculative content.

## Assumptions (Autonomous Run)

This UI-SPEC was generated without an interactive user available for follow-up
questions, per the orchestrator's instructions. `01-CONTEXT.md` decisions are treated as
authoritative; the calls below fill gaps CONTEXT.md left open (some explicitly delegated
as "Claude's Discretion," some inferred from CLAUDE.md's stack/visual-language
guidance). Flagging them here so planner/executor/checker can challenge any of them:

1. **Design system tooling = none.** shadcn is a React component library; this project
   is explicitly vanilla TypeScript with no framework (CLAUDE.md's "What NOT to Use"
   table). The shadcn gate therefore resolves to "not applicable," not "declined."
2. **Font = system UI stack**, not a custom webfont — zero network dependency, zero
   FOUT/FOIT risk, instant first paint. Matches the project's existing zero-extra-
   dependency ethos (CLAUDE.md names canvas-confetti as "the only runtime dependency
   this project needs").
3. **Target letter always displays uppercase**, even though the match check is
   case-insensitive (`KeyboardEvent.code`-based per CONTEXT.md). Physical keycaps are
   printed uppercase, so uppercase-on-screen keeps the visual-shape-to-key match direct
   for a pre-reading toddler.
4. **Exact hex values** for the "dark, pearlescent, deep blues/purples/greens, muted"
   palette (CLAUDE.md/PROJECT.md/CORE-05 describe it directionally; CONTEXT.md doesn't
   lock hex values). Chosen below with contrast-ratio math shown.
5. **Exact canvas-confetti tuning parameters** — CONTEXT.md explicitly delegates this to
   "Claude's Discretion." Concrete values chosen below so the executor isn't guessing.
6. **Exact animation durations/easing** for the glow-pulse (450ms) and incorrect-flash
   (150ms, per CONTEXT.md's explicit guidance) — also explicitly delegated discretion.
7. **Sequencing interpretation:** CONTEXT.md says a correct match "triggers a
   celebration and immediately selects a new target." Read literally + in service of
   the core value ("immediate ... feedback loop"), the new letter renders instantly and
   the celebration (glow + confetti) plays *on* the newly-arrived letter, rather than
   delaying the swap until the celebration finishes. See Motion Contract below.
8. **No "keyboard not detected" fallback UI in Phase 1.** A touch-only visitor sees the
   letter but has no way to trigger a match. Out of stated Phase 1 scope (no such
   requirement in REQUIREMENTS.md); flagged as an accepted gap, not silently unhandled.
9. **Pre-JS paint must already be the dark background color** (no white/blank flash
   before the state machine hydrates) — a reasonable extension of CORE-05's "never a
   full-page flash," even though CONTEXT.md doesn't spell out the pre-hydration frame.
10. **Destructive color token is a placeholder**, declared for palette forward-
    consistency but not exercised anywhere in Phase 1 (no destructive actions exist
    until Quit/Reset Stats in Phases 2 and 4).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Reserved (not exercised in Phase 1's single-element screen) |
| sm | 8px | Reserved |
| md | 16px | Root container's minimum edge safe-margin (see Exceptions) |
| lg | 24px | Reserved |
| xl | 32px | Reserved |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

Exceptions:
- The target letter's size is viewport-relative, not a fixed spacing-scale multiple —
  see Typography → Display. It is governed by CONTEXT.md's "~45% viewport height"
  decision, expressed as a clamped responsive value.
- Root container padding: `padding: max(16px, env(safe-area-inset-top))` (and
  right/bottom/left equivalents) — guarantees the letter and any confetti burst never
  render flush against a screen edge or under a device notch. env(safe-area-inset-*)
  falls back to 0 on non-notched devices, so the effective minimum is 16px (md) everywhere.
- No touch targets exist in Phase 1 (all interaction is physical-keyboard `keydown`,
  no clickable/tappable DOM elements) — the usual 44px minimum touch-target guidance
  does not apply here.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 28px | 700 (bold) | 1.2 |
| Display | `clamp(140px, min(45vh, 40vw), 560px)` | 700 (bold) | 1 |

Label/Body/Heading are declared for cross-phase consistency but are **not visibly used
in Phase 1** — the only on-screen typographic element is Display (the target letter).
Two weights total, per contract: 400 and 700.

**Display sizing rationale:** `min(45vh, 40vw)` combines CONTEXT.md's "~45% viewport
height" target with a width-based ceiling, so wide glyphs (`W`, `M`) at extreme
letter-spacing never overflow a narrow/portrait viewport. `clamp(140px, …, 560px)`
keeps the letter legible on very short viewports (e.g. landscape phone) and prevents
runaway sizing on very tall/large displays.

**Case:** always uppercase (assumption 3). Font weight for the display glyph is bold
(700) per CONTEXT.md's explicit "bold sans-serif" instruction.

## Color

Contrast for the primary reading pair is verified below (relative luminance method,
WCAG 2.x): foreground `#F3F1FA` on background `#0A0E1B` ≈ **17.8:1** — far exceeds the
7:1 AAA threshold, satisfying CORE-01's "high-contrast" requirement with large margin
for a pre-reading toddler audience.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0E1B` (`--color-bg`) | Full-bleed background — the near-black indigo "void" |
| Secondary (30%) | `#1E2340` (`--color-surface`) | Reserved for future chrome (Phase 2 menu cards/nav); also the tint used for the incorrect-key flash in this phase |
| Accent (10%) | `#8B7FFF` (`--color-accent`) | Celebration only — see "Accent reserved for" below |
| Destructive | `#C4607A` (`--color-destructive`) | Reserved placeholder — not used in Phase 1 (assumption 10) |

Additional token needed for this phase (template's 4 rows don't cover a light-on-dark
text/foreground color, which CORE-01/CONTEXT.md explicitly require):

| Role | Value | Usage |
|------|-------|-------|
| Foreground (on-dark) | `#F3F1FA` (`--color-fg`) | Target letter's resting-state color — soft "pearl white" (slight violet warmth) rather than pure `#FFFFFF`, for the pearlescent feel without going clinical |

**Accent reserved for:** the target letter's glow/pulse effect during the correct-match
celebration, and the confetti burst's anchor hue (see Motion Contract below). Not used
for any static/resting UI chrome — there is none in Phase 1 — which keeps the accent
color feeling special every time it appears, rather than diluted into everyday chrome.

**Confetti palette** (muted jewel tones spanning blue/purple/green per CORE-05, no
primary/neon rainbow colors):

```
CONFETTI_COLORS = ['#8B7FFF', '#4FD1C5', '#6E7FFF', '#B48CE0', '#3FAE8A']
```

**Note on "60/30/10" in a one-screen phase:** Phase 1's single full-bleed frame is, in
practice, ~90%+ dominant background + a small display glyph + occasional celebration
pixels — secondary and accent won't visually reach their nominal 30%/10% shares until
Phase 2 adds menu chrome. The roles/tokens are declared now for palette consistency
across phases; the proportions are an app-wide target, not a per-screen requirement.

## Motion & Celebration Contract

*(Supplementary section — Phase 1's core deliverable is this interaction loop, so
concrete timing/easing values are specified here rather than left to the executor to
invent. Not a template-default section; added because CORE-02 through CORE-05 are
fundamentally about motion, not static layout.)*

### Correct match (CORE-02, CORE-05)

Sequencing (assumption 7): the new target renders **instantly** on a correct keypress
(no delay) — the celebration plays *on top of* the newly-arrived letter, not as a
gate before it appears.

1. New target letter swaps in immediately, with a 100ms opacity crossfade
   (`transition: opacity 100ms ease-out`) so the change doesn't feel like an abrupt pop.
2. Simultaneously, the letter plays a scale/glow pulse:
   ```
   @keyframes correct-pulse {
     0%   { transform: scale(1);    filter: drop-shadow(0 0 0 transparent); }
     40%  { transform: scale(1.15); filter: drop-shadow(0 0 24px var(--color-accent)); }
     100% { transform: scale(1);    filter: drop-shadow(0 0 0 transparent); }
   }
   ```
   Duration: 450ms, easing: `ease-out`.
3. Simultaneously, a canvas-confetti burst fires from the letter's bounding-box center:
   - `particleCount: 40`
   - `spread: 60`
   - `startVelocity: 25`
   - `ticks: 150`
   - `gravity: 1`
   - `scalar: 0.8`
   - `colors: CONFETTI_COLORS` (see Color section)
   - `origin`: computed from the target letter element's screen position, not a fixed
     point — keeps the burst visually anchored to the glyph regardless of layout.

No full-page flash, no strobe (CORE-05) — all celebration is scoped to the letter and a
localized confetti burst, never a background-color change on `<body>`.

### Incorrect match (CORE-03, CORE-04)

- Duration: **150ms** (per CONTEXT.md's explicit guidance).
- The target letter itself does **not** move, scale, or shake — CONTEXT.md is explicit
  that this must never read as punitive.
- A subtle full-viewport background/border flash using the secondary surface tone at
  reduced opacity:
  ```
  @keyframes incorrect-flash {
    0%   { background-color: transparent; }
    30%  { background-color: color-mix(in srgb, var(--color-surface) 55%, transparent); }
    100% { background-color: transparent; }
  }
  ```
  Duration 150ms, easing `ease-out`. Reuses `--color-surface` rather than introducing a
  fifth color — incorrect ≠ error/destructive in this app's semantics.
- `event.repeat === true` keydowns are ignored entirely (CORE-04) — no flash, no
  celebration, no state change, per CONTEXT.md's key-repeat handling decision.

### Optional defensive polish (not required by REQUIREMENTS.md)

`prefers-reduced-motion: reduce` — if honored, drop the scale transform and confetti
particle count to near-zero, keep only the glow-color change as the correct-match cue.
Low implementation cost, good default; not gating this phase's completion since no
requirement mandates it.
