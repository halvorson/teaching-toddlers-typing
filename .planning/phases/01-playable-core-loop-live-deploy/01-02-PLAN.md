<objective>
Turn the deployed walking skeleton into the real Phase 1 game: a random A-Z target, physical-key
matching that is immune to Shift/Caps Lock/layout, an instant new target plus a muted pearlescent
celebration on a correct press, a neutral non-punitive flicker on a wrong press, a hard guard against
key-repeat spam, and a second live deploy that proves every push to main redeploys.

Purpose: this is the core value of the whole product — every correct physical key press produces an
immediate, delightful, low-stakes celebration. Everything in Phases 2-4 hangs off this loop.

Output: `src/game.ts`, `src/celebrate.ts`, an expanded `src/main.ts` and `src/style.css`, and a live
site at https://halvorson.github.io/teaching-toddlers-typing/ that a toddler can actually play.
</objective>

    - `LETTERS` — a frozen 26-element array of the uppercase characters A through Z, no digits.
    - `pickTarget(exclude?: string): string` — selects a random member of `LETTERS` using
      `Math.floor(Math.random() * n)` over an integer array index. When `exclude` is supplied, it must
      be impossible to return it: build the candidate pool by filtering `exclude` out first and index
      into that pool, rather than retrying in a loop. Integer indexing into a fixed-size array is what
      removes any rounding or tie-breaking ambiguity from selection.
    - `targetCode(letter: string): string` — returns the physical-key identifier for that letter by
      prefixing `Key` to it. A-Z map one-to-one onto these identifiers, so no lookup table exists.
    - `renderTarget(el: HTMLElement, letter: string): void` — assigns the letter to the element's
      `textContent` property (never by parsing an HTML string — 01-RESEARCH.md Security Domain) and
      re-triggers the 100ms opacity crossfade Plan 01's stylesheet already declares.

    named constant so Phase 2's larger Alphabet-completion burst can reuse the same palette.
