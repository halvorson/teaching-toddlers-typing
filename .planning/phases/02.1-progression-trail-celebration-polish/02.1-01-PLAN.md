<objective>
Build the ambient star trail end-to-end: a dedicated fixed full-viewport layer that gains one
small glowing dot on every correct key press during gameplay, sits strictly between the drifting
parallax background and all interactive/text UI, and starts empty on every mode entry.

Purpose: TRAIL-01. The child's reward for a correct match becomes cumulative and visible — the
background quietly "gets more cluttered" as the streak continues — without ever surfacing a
number, a counter, or a stats HUD.
Output: `src/trail.ts` (new module), the `#star-trail` / `.star-trail__star` CSS layer with the
coordinated z-index rewire of the existing drifting background, and the trail call sites wired
into `game-screen.ts`'s existing mount/unmount lifecycle and single keydown handler.
</objective>

Wire ONE entry point — a single correct key press in Letters mode — through every layer this

Create `src/trail.ts` with a module-level `let trailLayerEl: HTMLDivElement | null = null` and
exactly four exported functions, mirroring `menu.ts`'s module-level-state + mount/unmount shape:

- `mountTrailLayer(): void` — calls `unmountTrailLayer()` first (idempotent defensive guard,
  identical in spirit to `mountGameScreen`'s own opening `unmountGameScreen()` call at
  game-screen.ts:52), then `document.createElement('div')`, sets `id = 'star-trail'`, appends it
  to `document.body` (NOT to `#app`, whose children are wiped by `replaceChildren()` on every
  screen transition), and stores it in `trailLayerEl`. Because mount always starts from a
  freshly-created empty element, "each mode entry starts with an empty trail" falls out of the
  lifecycle with no extra reset call.
- `addTrailStar(): void` — returns immediately if `trailLayerEl` is null; otherwise creates a
  `div`, sets `className = 'star-trail__star'`, sets `style.left` to a template string of
  `2 + Math.random() * 96` suffixed with the viewport-width unit and `style.top` to an
  independent `2 + Math.random() * 96` suffixed with the viewport-height unit (uniform random
  inside a 2%-98% margin per axis, per UI-SPEC Placement — viewport-relative units so existing
  stars reposition naturally on window resize), and appends it to `trailLayerEl`.
- `clearTrail(): void` — `trailLayerEl?.replaceChildren()`, the codebase's established full-clear
  idiom (game-screen.ts:53, menu.ts:166). Exported now because plan 02.1-03 consumes it; it is
  not called from anywhere in this plan.
- `unmountTrailLayer(): void` — removes `trailLayerEl` from the DOM if present and resets
  `trailLayerEl` back to null, matching the reset-every-module-ref-to-null teardown shape of
  `unmountGameScreen()` and `unmountMenu()`.

Give the module a head comment explaining that this layer is purely decorative, surfaces no
numeric state of any kind, and is deliberately uncapped per the phase's locked decision.

In `src/style.css`, make ONE coordinated diff (both halves must land together or the two
background layers fight for the same stacking slot):

4. Add the base `.star-trail__star` rule: `position: absolute`, `width: 6px`, `height: 6px`,

   The muted 70%/45% derivations are deliberate — full-strength accent across a potentially
   hundreds-of-dots ambient layer would break the palette's "accent stays reserved" rule. No
   animation declaration in this task; Task 2 owns the pop-in.
