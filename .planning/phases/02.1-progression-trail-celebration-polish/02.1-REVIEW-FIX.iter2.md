## Fixed Issues

### WR-01: Stale Share-copy result can apply its "Copied!"/fallback UI to a since-remounted menu

**Files modified:** `src/menu.ts`
**Commit:** `19d5959` (prior run, already on `main`)
**Applied fix:** A `mountGeneration` counter is incremented on every `mountMenu()`/`unmountMenu()`
call; `runShare()` captures the generation at mount time and bails out if the counter has changed
by the time its `await shareCurrentUrl()` resolves, exactly as the review's suggested fix
described. Verified present in the current `src/menu.ts` (`mountGeneration` at lines 57, 186, 191,
205, 363) before starting this run's work.

### WR-02: Manual share fallback moves keyboard focus without going through `focusRow()`

### WR-03: `celebrate()`'s in-flight burst isn't cancelable on quit, unlike `celebrateAlphabetComplete()`

**Files modified:** `src/celebrate.ts`, `src/game-screen.ts`
**Commit:** `8211fa4`
**Applied fix:** Added a module-level `burstGeneration` counter in `celebrate.ts` and exported
`cancelPendingCelebration()`, which increments it. `fireBurst()` (the single dynamic-import site
shared by `celebrate()` and `celebrateAlphabetComplete()`) captures the generation before its
`await import('canvas-confetti')` and checks it again immediately after — if
`cancelPendingCelebration()` was called while the import was in flight, the burst is skipped.
`unmountGameScreen()` in `game-screen.ts` now calls `cancelPendingCelebration()` alongside its
existing `pendingCelebrationTimers.forEach(clearTimeout)`, so both the ordinary per-match path and
the Alphabet-completion path are protected against firing confetti on a screen the player has
already left. Verified with `tsc --noEmit` against the project's `tsconfig.json` — zero errors.

### WR-04: `readSettings()` returns the shared `DEFAULT_SETTINGS` object by reference

**Files modified:** `src/settings-store.ts`
**Commit:** `6e07d71`
**Applied fix:** All three fallback return sites in `readSettings()` (`!raw`, failed shape check,
caught exception) now return `{ ...DEFAULT_SETTINGS }` instead of the shared object reference, so
a future caller mutating the returned settings object can no longer corrupt the app-wide default
for the rest of the session. Verified with `tsc --noEmit` against the project's `tsconfig.json` —
zero errors.
